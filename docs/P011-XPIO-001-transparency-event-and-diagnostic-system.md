## Transparency event model

Every material action records:

- event ID and correlation ID;
- timestamp;
- human, model, agent, swarm, platform, or system actor;
- platform and model-line identity;
- object type and stable ID;
- input and output artifact references;
- result and severity;
- concise rationale summary;
- evidence, test, risk, gate, approval, cost, and duration references;
- correction, rollback, supersession, or retirement link.

Transparency records reviewable evidence and decisions. It does not require exposing private chain-of-thought, secrets, or restricted personal records.

## Time Machine interpretation

The event log, Git history, database migrations, snapshots, backups, corrections, and supersession records form a practical Time Machines Management System: past state can be reconstructed, present state audited, future scenarios tested, and unsafe changes rolled back.

## Diagnostic rule

A critical hash mismatch, identity failure, privacy-route violation, unknown permission, failed critical gate, invalid human approval, unauthorized financial action, or incomplete material correction blocks release.
